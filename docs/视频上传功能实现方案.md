# 视频上传功能实现方案

## 一、整体架构

```
浏览器                          后端 (:8081)                    MinIO
  │  (通过 Nginx 代理，/api 前缀)    │                              │
  │                               │                              │
  │  GET /api/upload/video/check  │                              │
  │  ?md5=xxx                     │  SELECT video_file            │
  ├──────────────────────────────>│  → {exists: false}            │
  │                               │                              │
  │  POST /api/upload/video/init  │                              │
  │  {filename,fileSize,md5,...}  │  createMultipartUpload ─────>│
  ├──────────────────────────────>│<── uploadId ─────────────────│
  │<── {uploadId, objectKey} ─────│  INSERT video_upload          │
  │                               │                              │
  │  POST /api/upload/video/chunk │                              │
  │  (multipart: uploadId,        │  uploadPart ────────────────>│
  │   chunkIndex, chunk bytes)    │<── ETag ────────────────────│
  ├──────────────────────────────>│                              │
  │<── {chunkIndex, etag} ────────│  (后端不落盘，直接透传到 MinIO)   │
  │                               │                              │
  │  ... 重复 N 个分片 ...         │                              │
  │                               │                              │
  │  POST /api/upload/video/      │                              │
  │       complete                │  completeMultipartUpload ───>│
  │  {uploadId, parts:[...]}      │<── 合并完成 ─────────────────│
  ├──────────────────────────────>│  MD5 校验 → INSERT video_file │
  │<── {videoId, url} ────────────│  UPDATE video_upload status=1 │
  │                               │                              │
  │  GET /api/video/play?videoId=1│                              │
  │  + Authorization: <token>     │  查 video_file → 生成签名 URL  │
  ├──────────────────────────────>│                              │
  │<── {url: "minio-host/...?     │                              │
  │        X-Amz-Expires=600..."}  │                              │
  │                               │                              │
  │  浏览器直连 MinIO 播放视频      │                              │
  ├──────────────────────────────────────────────────────────────>│
  │<────────────────────────────── 视频流 ────────────────────────│
```

核心技术栈：**Spring Boot 3.5 + AWS S3 SDK 1.12 + MyBatis-Plus + MinIO**

---

## 二、为什么用 AWS S3 SDK 而不是 MinIO SDK

MinIO Java SDK（8.x 全系）的低层分片 API（`createMultipartUpload`、`uploadPart`、`completeMultipartUpload`、`listParts`、`abortMultipartUpload`）只在内部使用，不对外暴露。`MinioClient` 只提供高层封装 `uploadObject(UploadObjectArgs)`，无法实现前端逐片上传的场景。

MinIO 完全兼容 S3 协议，所以改用 **AWS S3 SDK v1（1.12.782）**，关键配置：

```java
AmazonS3ClientBuilder.standard()
    .withEndpointConfiguration(
        new AwsClientBuilder.EndpointConfiguration(endpoint, "us-east-1"))
    .withPathStyleAccessEnabled(true)    // MinIO 使用 path-style URL
    .withCredentials(...)                // MinIO 的 accessKey / secretKey
    .build();
```

> **注意**：AWS SDK 1.x 已进入维护模式（2025/12/31 停维），但目前功能完全正常。后续可升级到 2.x，API 语义相同。

## 三、数据模型

### 3.1 video_file（文件记录，MD5 去重 + 播放入口）

```sql
CREATE TABLE video_file (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  md5         VARCHAR(32)  NOT NULL UNIQUE,
  object_key  VARCHAR(256) NOT NULL COMMENT 'MinIO 中的对象路径',
  file_size   BIGINT       NOT NULL COMMENT '字节',
  user_id     BIGINT       NOT NULL,
  created_at  DATETIME     DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id)
);
```

| 字段 | 说明 |
|------|------|
| `md5` | 文件 MD5，UNIQUE，秒传查询依据 |
| `object_key` | MinIO 存储路径，格式 `videos/{userId}/{yyyyMMdd}-{uuid}.mp4` |
| `id` | 自增主键，作为 videoId 返回给前端 |

### 3.2 video_upload（上传会话，断点续传 + 鉴权）

```sql
CREATE TABLE video_upload (
  upload_id    VARCHAR(256) PRIMARY KEY COMMENT 'S3 返回的 uploadId',
  user_id      BIGINT       NOT NULL,
  object_key   VARCHAR(256) NOT NULL,
  md5          VARCHAR(32)  NOT NULL,
  filename     VARCHAR(256) NOT NULL COMMENT '原始文件名',
  file_size    BIGINT       NOT NULL,
  total_chunks INT          NOT NULL COMMENT '总片数',
  content_type VARCHAR(64)  DEFAULT 'video/mp4',
  status       TINYINT      DEFAULT 0 COMMENT '0=上传中 1=已完成 2=已取消',
  created_at   DATETIME     DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user_id (user_id)
);
```

| 字段 | 说明 |
|------|------|
| `upload_id` | S3 Multipart Upload 返回的 uploadId，作为主键（VARCHAR(256) 因为 S3 uploadId 超过 100 字符） |
| `status` | 0=上传中, 1=已完成, 2=已取消——每步操作都校验 status |
| `total_chunks` | chunk 和 complete 时校验分片数是否匹配 |

### 3.3 状态机

| status | 含义 | 触发操作 |
|---|---|---|
| 0 | 上传中 | init 写入，允许 chunk |
| 1 | 已完成 | complete 成功后更新 |
| 2 | 已取消 | cancel / complete 异常时更新 |

## 四、API 接口

### 4.1 接口总览

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/upload/video/check?md5=xxx` | token | MD5 去重查询（秒传） |
| POST | `/upload/video/init` | token | 初始化分片上传 |
| POST | `/upload/video/chunk` | token + uploadId owner | 上传单个分片 |
| POST | `/upload/video/complete` | token + uploadId owner | 合并分片并落地 |
| GET | `/upload/video/progress?uploadId=xxx` | token + uploadId owner | 查询已完成分片 |
| GET | `/upload/video/cancel?uploadId=xxx` | token + uploadId owner | 取消上传 |
| GET | `/video/play?videoId=xxx` | token | 获取预签名播放 URL |

所有接口通过 token 鉴权。`uploadId` 相关接口额外校验 owner（`upload.user_id === currentUserId`）。

### 4.2 GET /upload/video/check — MD5 秒传

前端计算文件 MD5 后先调此接口。

**请求**：`GET /api/upload/video/check?md5=d41d8cd98f00b204e9800998ecf8427e`

**不存在**：
```json
{ "success": true, "data": { "exists": false } }
```

**已存在（秒传）**：
```json
{
  "success": true,
  "data": {
    "exists": true,
    "videoId": 42,
    "url": "/api/video/play?videoId=42"
  }
}
```

**后端逻辑**：
1. `UserHolder.getUser().getId()` 获取 userId
2. `video_file` 表 `WHERE md5 = ?` 查询
3. 有记录 → 返回 videoId + 播放 URL
4. 无记录 → 返回 `exists: false`

### 4.3 POST /upload/video/init — 初始化上传

**请求**：
```json
{
  "filename": "video.mp4",
  "fileSize": 52428800,
  "totalChunks": 10,
  "md5": "d41d8cd98f00b204e9800998ecf8427e",
  "contentType": "video/mp4"
}
```

**响应**：
```json
{
  "success": true,
  "data": {
    "uploadId": "minio-uuid-xxxx",
    "objectKey": "videos/1010/20260505-a1b2c3d4.mp4"
  }
}
```

**后端逻辑**：
1. token → currentUserId
2. 再次查 `video_file` 防并发重复
3. 构造 `objectKey = "videos/{userId}/{yyyyMMdd}-{uuid}.{ext}"`
4. `amazonS3.initiateMultipartUpload(bucket, objectKey)` → 得到 uploadId
5. `INSERT INTO video_upload`（status=0）
6. 返回 uploadId + objectKey

### 4.4 POST /upload/video/chunk — 上传分片

**请求**（multipart/form-data）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `uploadId` | String | init 返回的 uploadId |
| `chunkIndex` | int | 分片索引，从 0 开始 |
| `chunk` | file | 分片二进制数据 |

**响应**：
```json
{
  "success": true,
  "data": { "chunkIndex": 0, "etag": "\"abc123def456\"" }
}
```

**后端逻辑**：
1. token → currentUserId
2. 查 `video_upload` WHERE upload_id = ?
3. 校验 `upload.user_id === userId`（403）
4. 校验 `upload.status === 0`（400）
5. 校验 chunkIndex 在有效范围
6. `amazonS3.uploadPart(...)` → `partNumber = chunkIndex + 1`（S3 的 partNumber 从 1 开始）
7. 返回 ETag

**关键点**：后端全程不落盘，分片字节流读完即丢，直接透传到 MinIO。

### 4.5 POST /upload/video/complete — 合并完成

**请求**：
```json
{
  "uploadId": "uuid-xxxx",
  "parts": [
    { "partNumber": 1, "etag": "\"abc123\"" },
    { "partNumber": 2, "etag": "\"def456\"" }
  ]
}
```

**响应**：
```json
{
  "success": true,
  "data": {
    "videoId": 42,
    "url": "/api/video/play?videoId=42"
  }
}
```

**后端逻辑**：
1. token → currentUserId，校验 owner
2. 校验 `parts.length === upload.total_chunks`
3. `amazonS3.completeMultipartUpload(bucket, objectKey, uploadId, partETags)` → MinIO 合并分片
4. ETag 校验（`getObjectMetadata` 取得服务端 ETag，与前端传入的 MD5 比对）
5. `INSERT INTO video_file(md5, object_key, file_size, user_id)` → 拿到自增 id 即 videoId
6. `UPDATE video_upload SET status = 1`
7. 返回 videoId + 播放 URL

**异常处理**：合并失败 → `abortMultipartUpload` 清理 MinIO 临时分片 → `SET status = 2`

### 4.6 GET /upload/video/progress — 查询进度

**请求**：`GET /api/upload/video/progress?uploadId=uuid-xxxx`

**响应**：
```json
{
  "success": true,
  "data": {
    "objectKey": "videos/1010/xxx.mp4",
    "totalChunks": 10,
    "completedParts": [
      { "partNumber": 1, "etag": "\"abc123\"" },
      { "partNumber": 3, "etag": "\"ghi789\"" }
    ]
  }
}
```

**后端逻辑**：
1. token → userId，查 video_upload 校验 owner
2. `amazonS3.listParts(ListPartsRequest)` → MinIO 返回已上传分片列表
3. 前端对比 `totalChunks` 和 `completedParts`，跳过已上传的分片

### 4.7 GET /upload/video/cancel — 取消上传

**请求**：`GET /api/upload/video/cancel?uploadId=uuid-xxxx`

**响应**：`{ "success": true }`

**后端逻辑**：
1. token → userId，查 video_upload 校验 owner
2. `amazonS3.abortMultipartUpload(...)` → MinIO 清理临时分片
3. `UPDATE video_upload SET status = 2`

### 4.8 GET /video/play — 获取播放 URL

**请求**：`GET /api/video/play?videoId=42`（需附带 token）

**响应**：
```json
{
  "success": true,
  "data": {
    "url": "http://minio-host:9000/hmdp-videos/videos/1010/xxx.mp4?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Expires=600..."
  }
}
```

**后端逻辑**：
1. token → userId
2. `video_file` 表 `WHERE id = videoId`
3. 不存在 → `Result.fail("视频不存在")`
4. `amazonS3.generatePresignedUrl(...)` → 10 分钟有效预签名 URL → 返回给前端
5. 前端拿到 URL 后设给 `<video src="...">`，浏览器直连 MinIO 播放

## 五、鉴权设计

### 5.1 HTTP 接口鉴权

视频上传全套接口走项目现有鉴权链：

```
请求 → RefreshTokenInterceptor（读 Authorization header → 查 Redis → UserHolder.setUser()）
     → LoginInterceptor（检查 UserHolder → 无用户则 401）
     → VideoController
```

`MvcConfig.java` 改动：将 `upload/**` 排除登录改为精确排除 `upload/blog` + `upload/blog/delete`，使 `/upload/video/**` 需要登录，图片上传保持不登录。

### 5.2 uploadId 归属校验

chunk / complete / progress / cancel 四个接口额外校验 owner：

```java
VideoUpload upload = getById(uploadId);
if (!upload.getUserId().equals(currentUserId)) return Result.fail("无权操作此上传");
```

防止用户 A 拿到用户 B 的 uploadId 后越权操作。

### 5.3 安全模型

```
Bucket: hmdp-videos
策略:   private（禁止外部直接访问）

视频访问路径：
  1. 前端请求 /api/video/play?videoId=42（带 token 鉴权）
  2. 后端生成 10 分钟预签名 URL
  3. 浏览器直连 MinIO 播放（MinIO 验证签名）
  4. 10 分钟后 URL 失效
```

| 攻击方式 | 防护 |
|----------|------|
| 伪造 videoId 遍历 | `/video/play` 需要 token |
| 截屏分享视频 URL | 10 分钟过期 |
| 直接请求 MinIO | bucket 为 private |

## 七、关键实现细节

### 7.1 后端不落盘

chunk 接口直接读 `MultipartFile.getInputStream()` 传给 S3 SDK，不在本地文件系统写任何东西：

```java
UploadPartRequest partRequest = new UploadPartRequest()
    .withInputStream(chunk.getInputStream())    // 直接透传
    .withPartSize(chunk.getSize());
```

### 7.2 partNumber 转换

前端 chunkIndex 从 0 开始，S3 API 的 partNumber 从 1 开始：`int partNumber = chunkIndex + 1;`

### 7.3 MD5 校验

complete 时通过 S3 的 `getObjectMetadata` 获取服务端 ETag，与前端传入的 MD5 比对。分片 ≥ 8MB 时 MinIO ETag 等于文件 MD5。

### 7.4 upload_id 列长度

AWS S3 SDK 生成的 uploadId 长度超过 100 字符，`video_upload.upload_id` 需要 `VARCHAR(256)`，不能用 `VARCHAR(64)`。

### 7.5 文件大小限制

分两处设置：
- Nginx：`client_max_body_size 100M;`
- Spring Boot：`spring.servlet.multipart.max-file-size: 100MB`

### 7.6 objectKey 构造规则

```
videos/{userId}/{yyyyMMdd}-{8位uuid}.{扩展名}
```

示例：`videos/1010/20260505-a1b2c3d4.mp4`

按 userId 隔离 + 按日期分组，便于日后清理或统计分析。

## 九、启动与验证

### 9.1 前置条件

1. MinIO 已启动并可访问（默认 `http://127.0.0.1:9000`）
2. MySQL 中创建 `video_file` 和 `video_upload` 两张表
3. `application.yaml` 中配置正确的 MinIO 凭据

### 9.2 验证步骤

```bash
# 1. 启动应用，bucket 自动创建
mvn spring-boot:run

# 2. MD5 秒传查询（不存在）
curl "http://localhost:8081/upload/video/check?md5=test123" \
  -H "Authorization: <token>"
# → { "success": true, "data": { "exists": false } }

# 3. 初始化上传
curl -X POST "http://localhost:8081/upload/video/init" \
  -H "Authorization: <token>" \
  -H "Content-Type: application/json" \
  -d '{"filename":"test.mp4","fileSize":10485760,"totalChunks":2,"md5":"test123","contentType":"video/mp4"}'
# → { "success": true, "data": { "uploadId": "xxx", "objectKey": "videos/..." } }

# 4. 上传分片
curl -X POST "http://localhost:8081/upload/video/chunk" \
  -H "Authorization: <token>" \
  -F "uploadId=<上一步的uploadId>" \
  -F "chunkIndex=0" \
  -F "chunk=@part1.bin"
# → { "success": true, "data": { "chunkIndex": 0, "etag": "..." } }

# 5. 合并完成
curl -X POST "http://localhost:8081/upload/video/complete" \
  -H "Authorization: <token>" \
  -H "Content-Type: application/json" \
  -d '{"uploadId":"<uploadId>","parts":[{"partNumber":1,"etag":"..."},{"partNumber":2,"etag":"..."}]}'
# → { "success": true, "data": { "videoId": 1, "url": "/api/video/play?videoId=1" } }

# 6. 获取播放 URL
curl "http://localhost:8081/video/play?videoId=1" \
  -H "Authorization: <token>"
# → { "success": true, "data": { "url": "http://127.0.0.1:9000/hmdp-videos/...?X-Amz-..." } }

# 7. 浏览器打开预签名 URL，播放视频
```

## 十、与现有能力的关系

| 能力 | 复用方式 |
|------|----------|
| Token 鉴权 | 复用 `RefreshTokenInterceptor` + `LoginInterceptor` |
| 用户信息 | `UserHolder.getUser()` → userId |
| Redis Token 存储 | `login:token:{token}` |
| MyBatis-Plus CRUD | `ServiceImpl<Mapper, Entity>` 标准模式 |
| 响应格式 | `Result.ok(data)` / `Result.fail(msg)` |
| 全局异常处理 | `WebExceptionAdvice` 捕获未处理异常 |
| 图片上传 | `POST /upload/blog` 保持不变，互不影响 |
